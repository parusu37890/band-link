# 0005: 利用停止中の画面と、解除後の募集の扱い

## 確定：停止中はログイン後に案内だけを見せる

requirements.md 3章「利用停止中のログイン後画面には停止案内と問い合わせ先だけを表示する」に対し、実装は通常のアプリをそのまま表示していた。停止に気づくのは投稿やメッセージを試して409が返ったときだけで、理由も連絡先も分からない行き止まりだった。

ログイン後は停止の案内・状況説明・問い合わせ先・ログアウトのみを表示し、ヘッダーのナビゲーションも外す。`/support`だけは例外として到達可能にする（連絡先がそこにあるため）。ログアウトを停止画面に置いたのは、設定画面へ行けなくなるとログアウト手段が無くなるため。

## 未決：解除しても募集が戻らない

利用停止時、その人の募集は`CLOSED(closed_reason=SUSPENDED)`になる。`docs/db-api-design.md` §3.2は`CLOSED(SUSPENDED)`からの再公開を不可としているため、**運営が停止を解除しても募集は戻らず、本人も再公開できない**。実測でも、解除後にプロフィールは公開に戻る一方、募集10件は`CLOSED/SUSPENDED`のまま一覧に戻らなかった。

実装は設計書どおりで不具合ではない。ただし結果として、誤って停止した場合や、警告目的の短期停止を解除した場合でも、本人は募集を書き直すしかない。妥当かどうかは運営方針の判断が要る。

考えられる選択肢:

1. **現状維持** — 停止は重い措置であり、解除後は本人が改めて出し直す。実装変更なし。
2. **解除時に復帰させる** — 解除操作で`CLOSED(SUSPENDED)`を`OPEN`へ戻す。掲載期限（30日）と1人1件の制限をどう再計算するかを決める必要がある。
3. **本人が再公開できるようにする** — 解除後に限り`CLOSED(SUSPENDED)`を再公開の対象に含める。§3.2の状態遷移表の変更にあたる。

この判断が出るまでは1（現状維持）のまま。
