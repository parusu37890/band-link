# 0006: 運営への問い合わせ先

## 見つかった行き止まり

requirements.md 3章は「利用停止中のログイン後画面には停止案内と問い合わせ先だけを表示する」と定めている。
実装はその指示どおり、停止画面に「お問い合わせ先を見る」ボタンを置き`/support`へ送っていた。

しかし`/support`には連絡先が一つも書かれていない。文面は「運営へご連絡ください」「運営への連絡先。」と
繰り返すだけで、宛先・フォーム・手順のいずれも無い。停止された人は、そこからは何もできない。

requirements.md 11章（保留事項）が「管理権限の付与方法、**問い合わせ先**、通報処理の状態と記録保持を
具体化する」と挙げているとおり、問い合わせ先はまだ決まっていない。決まっていないものを画面が
約束していた、というのが実態である。

## 今回とった対応

連絡先を作り出すことはできないので、画面が事実だけを言うようにした。

- `/support` を、実際に解決できる画面へ着地する項目の一覧に作り直した。通報の導線は実在するので明記する。
- 通報で扱えない件（利用停止など）については「問い合わせ先はまだ公開していません。決まりしだいこの
  ページに掲載します」と書いた。無い連絡先を指し示すのをやめた。
- 停止画面のボタンは「ヘルプを見る」に変え、解除を申し出る手段がまだ無いことを本文で伝える。

decision 0005 は`/support`を例外的に到達可能とした理由を「連絡先がそこにあるため」としていたが、
その前提は成り立っていなかった。到達可能にしておく判断自体は変えない（停止中に読める唯一の説明であるため）。

## 決めてほしいこと

問い合わせをどの経路で受けるか。

1. **メールアドレスを公開する** — 実装は文言だけ。運用（受信者・返信体制）を決める必要がある。
2. **問い合わせフォームを作る** — 停止中でも送信できる必要があるので、認証と権限の扱いを設計する。
   停止アカウントからの送信をどう受けるかが論点になる。
3. **外部サービスへ委ねる** — フォームや窓口を外部に置き、リンクだけを載せる。

決まるまでは現状（連絡先を公開していないと明記する）のまま。宛先が決まれば`/support`の
`.help-contact`節を差し替えるだけで済む。
