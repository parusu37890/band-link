# 0012: 募集一覧ページに非表示h1を置く

- 状態: 確定（2026-09-15）
- 関連: `docs/test-plan/latest-change-inconsistencies.md`の未確定事項4

## 背景

2026-09-15の仕様変更で、募集一覧（`/posts`）から視覧見出し`<header class="board-heading"><h1>バンドメンバー募集</h1></header>`を削除した（サイトヘッダーの「Band Link」ワードマークとナビゲーションの「仲間を探す」がすでに現在地と趣旨を示しており、本文側の大見出しは冗長と判断したため）。

削除後、確認したところ`/posts`ページにはページ内に`<h1>`が一つも存在しない状態になっていた（サイトヘッダーの`<header>`要素はランドマークではあるが見出し要素を持たない）。他の全画面（詳細、プロフィール設定、ヘルプ、マイページ等）は`page-heading`パターンや`auth-page`パターンで必ず`<h1>`を持っており、一覧ページだけが例外だった。

## 決定

`/posts`の一覧ページに、視覚的には非表示（`.sr-only`）の`<h1>バンドメンバー募集</h1>`を追加する。実装は`recruitment-search.js`の`listing()`が返すHTMLの先頭、`.discovery-page`直下に配置した。

非表示・可視の二択のうち非表示を選んだ理由:

- 可視の見出しを復活させると、今回削除した理由（サイトヘッダーとの視覚的重複）が再発する。
- 一方でページの見出し階層（1ページに`h1`が1つ、以降`h2`・`h3`と積み上がる構造）と、スクリーンリーダー利用者が見出しジャンプでページの主題をすぐに把握できることは、視覚的な見た目とは独立した要件であり、削除してよい理由にならない。
- `.sr-only`は`base.css`ですでに使われている既存パターン（例: 並び順セレクトのラベル）で、新しい仕組みを持ち込まずに済む。

サイトヘッダーの`<header>`要素をランドマークのbanner roleとしてh1代わりに扱う案は採らなかった。`<header>`は各ページ共通の全画面固定要素であり、ページごとに異なる主題を表すh1の役割を代替できないため。

## 影響

- `recruitment-search.js`の`listing()`にのみ影響。他の画面（詳細ページの`<h1 class="detail-title">`等）は変更なし。
- 見出し階層はh1（非表示、募集一覧）→h2「条件検索」／各投稿カードのh2見出し、という構成になる。

## 検証

公式Playwright MCPで`/posts`のaccessibility snapshotとDOMを確認し、`h1.sr-only`が1件のみ存在し可視領域には現れないこと（デスクトップ1440px・モバイル390pxのスクリーンショットで確認）、見出し階層がh1→h2の順で破綻していないことを確認した（記録: `docs/test-results/2026-09-15-post-spec-followup.md`）。
