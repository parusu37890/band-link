今回追加した成果物はテスト文書、テストデータ、テストコードだけです。本番コードは変更していません。Sol は設計と静的確認だけを行い、JUnit、結合テスト、SQL投入、アプリ起動、Playwright MCP操作は実行していません。

## 5. 環境とデータ分離

- DB は `band_link_release_test` だけを使います。seed SQL はDB名を検査し、別DBなら例外で中止します。
- `band_link` には接続しません。Runa は `SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/band_link_release_test` を明示します。
- 画像保存先は専用の空ディレクトリにします。本番・開発用 `uploads` を共用しません。
- メールは外部配信せず、ローカルSMTP受信箱を使います。LINE実往復は専用テストチャネルがある場合だけ実施します。
- 固定IDは利用者 `910001..910025`、ページング用利用者 `910101..910160`、投稿 `920001..920160`、会話 `930001..`、メッセージ `940001..`、通知 `950001..` を使います。
- テスト間で更新したデータはケースの後処理に従って戻します。破壊的ケース後はseedを再投入し、次のケースへ進みます。

## 7. 既知の高リスク差分（実行前から要確認）

静的確認で次を検出しました。テストの期待値は要件側に置いており、現実装に合わせて弱めていません。

1. `/uploads/**` が公開される構成と、DM画像の認可付きURLが同じ物理保存域を共有しています。DM画像の公開URL迂回はP0です。
2. 画像はマジックバイトだけで判定しており、デコード不能な切断画像を拒否できない可能性があります。
3. 本人退会処理に問い合わせ・機能要望の外部キー処理が見当たりません。問い合わせ済み利用者の退会はP0です。
4. 登録サービスのSpring注入経路で、プロフィールのマスタ関連を保存するRepositoryが渡されない構成に見えます。登録直後の必須プロフィール保存を結合確認します。
5. 停止ユーザーを全APIで一律に止めるサーバー側ゲートがなく、URL/API直アクセスの権限差を確認します。
6. メッセージ通報は対象会話の参加者かを確認せず、第三者がIDを指定できる可能性があります。
7. 投稿一覧ページングは全件取得後にメモリで切り出し、巨大な数字のcursorは整数変換で失敗する可能性があります。
8. 投稿の同時公開1件、12時間制限、画像5枚上限にDBロックまたは一意制約が見当たらず、同時要求を確認します。
9. 検索キーワードが補足エリアを対象にしていない一方、承認済み設計では対象です。
10. 要件の初期マスタ件数と現在のinitializer、活動頻度の選択肢に差があります。

これらは「既知の不具合」と断定せず、該当ケースがFAILした時点でリリース阻止事項にします。

## 8. 証跡規約

証跡ルートは `docs/test-results/<実行日時>/` とし、ケースIDをファイル名の先頭にします。最低限、画面は操作前・結果・エラー、APIはmethod/path/status/必要最小限のbody、DBは個人情報とハッシュを除く照合結果、JUnitはXMLとテキストログを保存します。パスワード、CSRF token、メール確認token、再設定token、Cookie、LINE資格情報は証跡へ残しません。

## 9. 変更・再試験

FAIL修正後は、該当ケース、同じ要件IDの全P0/P1、隣接する状態遷移、単体・結合の全件を再実行します。同じ原因で3回失敗した場合は `docs/engineering-method.md` に従い、再現条件、試行、ログ、未確認仮説を揃えてエスカレーションします。

## 10. 対応率の定義

`traceability-matrix.csv` の確定要件行について、1件以上のテストケースが割り当てられていれば設計対応済みと数えます。今回の設計対応率は100%です。これは**設計上の紐付け率**であり、合格率や実行済み率ではありません。実行済み率は0%です。
