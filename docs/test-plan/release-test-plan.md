## 1. 目的と判定対象

この計画は、Band Link を公開してよいかを、利用者の主要行動、データ整合性、権限、障害回復、画面品質から判定するためのものです。対象は現在の作業ツリーです。既存の未コミット変更も含むため、Runa は実行開始時に `git rev-parse HEAD` と `git status --short` を証跡へ保存し、途中でソースを変更しません。

今回のリリース確認では、テスト文書・固定テストデータ・テストコードに加え、DM/Feedback画像の公開経路を分離する認可修正を適用しました。2026-09-15に通常単体98件、PostgreSQL結合19件、業務状態マトリクス14,227件を実行し、すべて成功しました。公式Playwright MCPはこのセッションに提供されていないため、最新UIに対する新規システムテストは未完了です。

## 5. 環境とデータ分離

- DB は `band_link_release_test` だけを使います。seed SQL はDB名を検査し、別DBなら例外で中止します。
- `band_link` には接続しません。Runa は `SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/band_link_release_test` を明示します。
- 画像保存先は専用の空ディレクトリにします。本番・開発用 `uploads` を共用しません。
- メールは外部配信せず、ローカルSMTP受信箱を使います。LINE実往復は専用テストチャネルがある場合だけ実施します。
- 固定IDは利用者 `910001..910025`、ページング用利用者 `910101..910160`、投稿 `920001..920160`、会話 `930001..`、メッセージ `940001..`、通知 `950001..` を使います。
- テスト間で更新したデータはケースの後処理に従って戻します。破壊的ケース後はseedを再投入し、次のケースへ進みます。

## 7. 既知の高リスク差分（実行前から要確認）

実行前に検出した高リスク差分と、今回の再実行で残った確認事項を分けて記録します。

1. DM/Feedback画像の公開URL迂回はSecurityConfigのdenyルールを追加し、SEC-011回帰と結合APIで403を確認済みです。
2. 画像の形式・切断データ境界は単体と業務マトリクスで確認済みですが、実ブラウザーからの各形式アップロードはシステムテストで再確認が必要です。
3. 問い合わせ済み利用者の退会とFeedback外部キーは結合テスト19/19で確認済みです。
4. 登録時プロフィール関連保存は結合テストと全業務マトリクスで確認済みです。
5. 停止ユーザーを全APIで一律に止めるサーバー側ゲートがなく、URL/API直アクセスの権限差を確認します。
6. メッセージ通報の参加者認可とIDORは結合テスト・業務マトリクスで確認済みです。
7. 巨大cursorは結合テストと業務マトリクスで500にならないことを確認済みです。全件取得方式の性能はNFTで確認が必要です。
8. 投稿の同種別公開1件、12時間制限、画像5枚上限にDBロックまたは一意制約が見当たらず、同時要求を確認します。募集と加入希望の異種別2件は同時公開できる必要があります。
9. 要件の初期マスタ件数と現在のinitializer、活動頻度の選択肢に差があります。

残る項目（同時投稿のDB一意性、マスタ件数・頻度、実機性能、公式Playwright回帰）は、該当証跡が揃うまでリリース阻止事項として扱います。

## 8. 証跡規約

証跡ルートは `docs/test-results/<実行日時>/` とし、ケースIDをファイル名の先頭にします。最低限、画面は操作前・結果・エラー、APIはmethod/path/status/必要最小限のbody、DBは個人情報とハッシュを除く照合結果、JUnitはXMLとテキストログを保存します。パスワード、CSRF token、メール確認token、再設定token、Cookie、LINE資格情報は証跡へ残しません。

## 9. 変更・再試験

FAIL修正後は、該当ケース、同じ要件IDの全P0/P1、隣接する状態遷移、単体・結合の全件を再実行します。同じ原因で3回失敗した場合は `docs/engineering-method.md` に従い、再現条件、試行、ログ、未確認仮説を揃えてエスカレーションします。

## 10. 対応率の定義

`traceability-matrix.csv` の確定要件行について、1件以上のテストケースが割り当てられていれば設計対応済みと数えます。今回の設計対応率は100%です。これは**設計上の紐付け率**です。現行作業ツリーでは、JUnit DynamicTest 14,227/14,227、通常JUnit 14,325/14,325（19件は専用結合へ分離）、PostgreSQL結合19/19がPASSです。
