## ST-01 登録

| | |
|---|---|
| 手順 | `/register` を開き、表示名「ST検証A」・メール `st-a1@bandlink.local`・パスワードを入力し「アカウントを作成」を押す |
| 期待 | アカウントが作られ、ログイン状態でメールアドレス確認へ進める |
| 実結果 | **不合格。** ユーザーは作成された（id 30、`email_verified_at` NULL、トークン発行済み）が、`/posts` へ遷移した先で**未ログイン**だった |

`GET /api/auth/me` が401を返し、ヘッダーは「ログイン」「新規登録」を表示。
「アカウントを作成しました。」というトーストの直後に、匿名の閲覧者として掲示板に置かれる状態だった。

**原因**：`AuthController.register` は201でユーザーを返すだけでセッションを作らない。
セッションを張るのは `login` のみ。フロント（`account.js`）は `state.user=response` として
ログイン済みとして扱い `location.assign(next)` するため、再読み込み後に実態が現れる。

新規登録者はログインが必要なことも、メールアドレスの確認が必要なことも知らされない。
確認画面（`/verify-email`）にも到達しないため、**投稿とメッセージ送信に進めない**。

**修正**：

- `register` にセッション確立を追加。`login` と共通の `startSession` に切り出し、両方から呼ぶ。
  ログイン日時の更新（`touchLogin`）も共通化した。
- 登録後の遷移先を `next` から `/verify-email` に変更。ログイン済みだが確認前という状態で、
  次に必要な操作の画面へ着地させる。
- 確認完了時の文言を、ログイン済みなら「募集の投稿とメッセージの送信ができます。」に切り替え。
  従来は常に「ログインすると募集を投稿できます。」で、ログイン済みの読み手には合わなかった。
- 回帰テスト `AuthSessionTest` を追加（登録でセッションが張られること、ログインが自前で
  セッションを張ること）。
